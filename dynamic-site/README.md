# Saem dynamic-site prototype

This is the first local vertical slice for the Exam Time Matrix: a small
dynamic learning page calls a versioned API, and the API invokes the existing
C17 `cos_rat` implementation. The browser does not reimplement or emulate the
kernel.

## Run locally

From the repository root:

```sh
python3 dynamic-site/server.py
```

Open `http://127.0.0.1:8000`. The development server binds only to loopback,
builds the C17 bridge into a temporary directory, and removes that build when
the server exits. Use Ctrl+C to stop it.

This prototype is not a public deployment. It has no accounts, question
extraction/import, exam scoring, question prediction, or student data storage.
Do not expose the development server to a network. The production frontend/API
hosting and student authentication remain future work.

## Private Cloud Run preview

The repository-root `Dockerfile` builds the C17 bridge into a small runtime
image. The `.dockerignore` allowlist excludes the paper folders, the generated
paper inventory, books, and unrelated repository files from the build context.
The image starts with empty exam folders and an empty inventory; it contains no
exam PDFs or extracted question content. The container runs as an unprivileged
user and listens on Cloud Run's `PORT`. The default local server bind remains
`127.0.0.1`; the container explicitly opts into `0.0.0.0`.

The service must remain IAM-authenticated (`--no-allow-unauthenticated`).
Cloud Run does not turn a private service URL into a student-ready login flow.
For an authorized developer preview, deploy from the repository root:

```sh
gcloud config set project PROJECT_ID
gcloud services enable run.googleapis.com cloudbuild.googleapis.com
gcloud run deploy saem-exam-preview \
  --source . \
  --region REGION \
  --no-allow-unauthenticated \
  --port 8080 \
  --memory 512Mi \
  --cpu 1 \
  --max 2 \
  --concurrency 10 \
  --timeout 30
```

Grant `roles/run.invoker` only to the preview reviewers. To use the page with
Cloud Run IAM authentication, run the authenticated local proxy:

```sh
gcloud run services proxy saem-exam-preview --region REGION --port 8080
```

Then open `http://127.0.0.1:8080`. Verify the page and `/api/v1/health` through
the proxy before sharing the service URL. Deployment requires an authorized
Google Cloud project, billing, and `gcloud`; those are not stored in the
repository. Do not remove IAM authentication or grant public invoker access
for this preview. A public student deployment requires a separately designed
login, privacy, rate-limit, monitoring, and approved-content flow.

## Verify

```sh
python3 -m pip install -r dynamic-site/requirements.txt
python3 dynamic-site/test_server.py
python3 dynamic-site/test_exam_content.py
```

The test suite compiles the bridge against the repository's C17 `cos_rat.c`
and checks exact results, explicit kernel refusals, bounded HTTP input,
versioned routes, and the local page. The content-contract tests validate the
versioned JSON Schema, record relationships, source hashes, and the separate
paper/question/solution review gates.

## Paper corpus and content contract

`data/paper_inventory.json` is generated by
`python3 dynamic-site/inventory_exam_papers.py`. It records source paths,
SHA-256 digests, byte sizes, per-source owner verification, and whether a PDF
header appears within the first 1024 bytes. Starting
the dynamic site refreshes this inventory and then checks the three source
folders every two seconds. PDFs added, changed, or removed while it is running
are reflected automatically; `GET /api/v1/papers` returns the latest manifest.
To refresh without starting the site, run the generator command above. This
records and machine-checks files only; it does not extract questions, confirm
metadata or redistribution rights, or approve content for student mocks. It
does not alter or copy the exam files. The header check is not a full PDF
parser. Owner paper-level verification remains attached only to previously
attested files whose hashes still match; a newly discovered PDF starts as
`not_reviewed`. File discovery does not grant publishing permission.

`data/exam-content.schema.json` defines the version 1 content contract.
Validate a candidate content JSON file with:

```sh
python3 -m pip install -r dynamic-site/requirements.txt
python3 dynamic-site/validate_exam_content.py path/to/exam-content.json
```

Validation also checks references between sources, papers, rules, topics,
questions, and solutions, then verifies source hashes against the corpus
inventory and files on disk. A record is not public-mock eligible until its
paper, question, and solution are owner-reviewed and its source's
redistribution permission is confirmed. Scoring and numeric answers use
reduced rational strings within the C17 kernel's exact signed-64-bit range.
